# Standing calibration for roster-slimming dispatches

Every slimming dispatch reads this. It is the accumulated cost of the lanes that ran before yours — each line is a mistake already paid for once.

## Authority order

1. **Your task in `~/worklogs/portable-skills/plans/roster-slimming.md`** (or `review-machinery.md` for briar/eric/review-loop). Winston wrote it from source. It wins.
2. **`SLIMMING-GUIDE.md`** — the rubric, rules 1–8.
3. **The dispatch brief.** Lowest authority, and the most likely to be wrong — see below.
4. **`ROSTER-AUDIT.md`** is context only. It was written against a tree five commits stale and several of its per-skill claims are recall rather than source. Never trust its line anchors.

## Verify the brief before you obey it

Six dispatch briefs in this run have contained a factual error about the file under edit — a protected item that didn't exist, a restatement claimed in the frontmatter that wasn't there, a line anchor off by twenty lines.

**If the brief says to protect something you cannot find in the file, say so in your report and move on. Do not write it in to satisfy the brief.** Two agents have already done this correctly and both were right.

Re-derive every line anchor from the file itself.

## The word figure is an expectation, never a gate

Nine skills have landed at **16–38%** cut against expectations set near 60%. The 78% exemplar was winston-specific: its bulk was personality prose, an 11-section output template, and a checklist, all near-fully compressible. Skills carrying reference density — templates, tables, framework matrices — do not compress that far.

If the keep-list and the number conflict, **the keep-list wins and you report the conflict.** Never cut protected content to hit a number. Never manufacture cuts to match a sibling's ratio.

## What "protected" means for a cognitive lens

It means **keep the discriminator, drop the Trigger/Escape scaffolding** — one working instruction per lens. It does *not* mean leave the block untouched. One agent read "protected" the second way and landed at 10 surviving Trigger/Escape pairs where its siblings landed at 0.

The exception is a genuine escape-condition block — routing for when work cannot proceed. Those survive as working instructions; the guide's Part 3 protects them explicitly. Ellis's `## When Things Break in the Model` is the example. Penny's near-identical-looking block was partly redundant with its lens escapes and was a dedup target instead. Read yours before deciding which it is.

## Never slim a `description` frontmatter

It is the skill's trigger mechanism, and Claude already under-triggers skills. Verify byte-identical when you finish, using the awk form:

```
diff <(git show <base>:skills/<name>/SKILL.md | awk 'NR==1&&/^---$/{f=1;next} f&&/^---$/{exit} f') <(awk 'NR==1&&/^---$/{f=1;next} f&&/^---$/{exit} f' skills/<name>/SKILL.md)
```

Not `sed -n '/^---$/,/^---$/p'` — that false-positives on any file whose body contains a `---` horizontal rule.

## Absence checks

Write them as `! grep -q` or an explicit count comparison, never `grep -c <pat> && <next>` — a zero count exits non-zero and silently kills the rest of the chain. That produced a falsely-reported exit code earlier in this run. Pair every absence check with a positive control proving the probe reached the file.

Where a probe's verdict is a printed value (`wc -w`, `grep -c`, `grep -rln`), read the printed value, not `$?`.

## `$ARGUMENTS`

Keep it as a standalone line outside any bulleted list. One rewrite left it mid-list, which would inject raw user text between two bullets on every invocation, and cost a follow-up fix.

## The renderer trap

`render-agents.py` scans only the SKILL.md **body** for `_shared/<name>.md` citations. A citation relocated into a `references/` file silently drops that fragment from the persona's generated toml. Keep every `_shared/…` citation in the body.

## Scope discipline

- **Do NOT** branch, commit, push, run `sync.sh`, or run `render-agents.py`. Lanes run concurrently and collide on the renderer; one terminal run happens after everything lands.
- Touch only your own skill's files. Scope every diff: `git diff --stat -- skills/<name>/`.
- Other files will show as modified in `git status`. Those are sibling lanes, not stray edits. Two agents have flagged this; the answer is always "expected."
- Delete only what your task authorizes. Anything else that looks like dead weight goes in your report, not the bin.

## The business-layer citation line

Business skills replace their strategy-doc restatement with this, adapting only the owned-sections clause:

> Your single durable artifact is the strategy doc — the business layer's working memory, company/quarter-scoped (it sits above PRDs on grain, not tied to any ticket). Location, shape, ownership rules, the create-lazily rule, and the `OPEN — TBD` variant all live in `skills/_shared/strategy-doc.md` — read it, don't restate it.

## Report-back

verdict (`done`|`needs-replan`|`needs-stronger-model`|`needs-human`|`blocked`), one-paragraph summary, artifacts touched, `Confidence`, `Escalate`, plus `filesChanged`, `verificationCommand`, `verificationExitCode`, and before/after word count.

Report every overage, every brief error you found, and every judgment call you made. Nothing here is graded on hitting a number.
